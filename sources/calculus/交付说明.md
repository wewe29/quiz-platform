## 三、快捷键

|---|---|---|---|
| `←` / `→` | 上一题 / 下一题 | `A`–`D`、`1`–`4` | 选对应选项 |

> 曾经选项自带 `keydown → onPick`，和全局的 `Enter=提交` 抢键，多选题上按 Enter 会把刚选的

构建期门禁（任一不过即构建失败）：LaTeX 转义扫描 / 答案键 ↔ 解析自洽审计 / 主观题结构审计 /

真实 `filters.chipKeys` 逐个 chip 验证「标注题数 == 实际选中题数」，且没有 0 题的死入口）/
**键盘快捷键契约**（用真实 `render.js` + 真实 `keys.js` 跑真实按键路径，验证 Enter/空格不被选项抢占、
已选答案不会被取消）/ 悬空导出基线比对 / script 结构解析 / 内联题库接线检查 /
成品 ↔ 源码逐字段一致 / 零外部资源引用。


> ⚠ **必须用 `tools\serve.py` 做浏览器验收**：`python -m http.server` 不发 `Cache-Control`，
> Chromium 启发式缓存会让你以为「改了代码却跑旧代码」。

## 七、线上问题修复记录

| 编号 | 症状 | 根因 | 现状 |
|---|---|---|---|
| BUG-12 | **多选题上按 `Enter` 提交不了**（点「提交答案（Enter）」按钮却完全正常） | 选项元素自带 `keydown` 监听：`Enter`/`空格` → `view.onPick(L)`，和全局快捷键「`Enter` = 提交答案」抢同一个键。事件先落到选项 → 多选题的 `onPick` 是 toggle（再点一次＝取消）→ 刚选的答案被自己抹掉；事件再冒泡到全局 → 提交时缓冲区已空 → 弹「还没作答，先选一个选项」。单选题不受影响（`onPick` 是赋值），所以只有多选题坏、且只有纯键盘路径坏 —— 自测与数据门禁全都照不到 | 已修：选项元素不再挂 `keydown`，键盘选择统一交给全局的 `A`–`D`/`1`–`4`，`Enter` 归提交、空格归翻题；新增构建门禁 `tools\check_keyboard_contract.js`（用真实 `render.js` + 真实 `keys.js` 跑真实按键路径，断言选项无 keydown、Enter 触发提交、已选字母不被取消、点击仍能选）并做过**反向验证**（把有缺陷的 keydown 放回去 ⇒ 门禁报错退出 1）。2026-10-31 已重建三件产物并原地更新三个节点，线上实测 `Enter` 提交成功 |
| BUG-11 | 点章节 chip「函数与极限(154)」显示**没有题目** | chip 的 key 是字符串 `"1"`，题目的 `chapter` 是数字 `1`；`session.passes` 用 `f.chapters.indexOf(q.chapter)` 比较，`["1"].indexOf(1) === -1` ⇒ 命中 0 题。而括号里的数字由 `tally` 按字符串归一统计，所以**计数与筛选用了两套 key 空间** | 已修：`passes()` 统一按 `String()` 归一比较（数字 key 的旧存档也能匹配）；新增构建门禁 `tools\check_filter_keys.js`，用**真实的** `session.passes` + **真实的** `filters.chipKeys` 逐 chip 验证「标注题数 == 实际选中题数」且「0 题项不得出现在界面上」；界面已隐藏 11 个 0 题的死入口 |
| BUG-10 | 单文件离线包打开是空白 | `bank.setInline` 定义了却从没被调用（还被登记进悬空导出基线），运行时去 fetch `data/index.json` 必然 404；且内联模式跳过 `bank.loadIndex()` 导致 catalog 不合并、筛选全空 | 已修：`app.js` 接线 `bank.setInline(window.__BANK__)`、`load()` 统一走 `bank.loadIndex()`；门禁增加「内联接线检查」，悬空导出基线不再允许登记运行模式切换类 API |
| BUG-1 | 全站公式退化成 LaTeX 源码，但页面零报错 | 多文件站 `index.html` 出现 `<script><script src=…>` 嵌套，HTML 解析器把外层当纯文本 ⇒ KaTeX 从未加载 | 已修：改构建器；新增 `check_html.scan_scripts()` 按 HTML 规则解析 script 元素，检测嵌套 / 多余 / 未闭合 + 外链文件是否真落地 |

> 这些缺陷的共同点：**数据层完全正确，坏在装配 / 渲染 / 接线层**。
> 静态门禁全绿 ≠ 运行时没问题 —— 每道新门禁都做过反向验证（撤掉修复 → 门禁必须精确报错）才敢信。
