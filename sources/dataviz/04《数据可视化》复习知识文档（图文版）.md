### 1.1 什么是数据可视化

#### 1.1.1 数据可视化的发展历史 ⭐重点 📖必背

数据可视化有着非常久远的历史，最早可以追溯至10世纪，至今已经应用和发展了数百年。五个发展阶段：

- **（1）10世纪：图表萌芽**——人们受到宗教的影响，对天文学的研究较早。

- **（3）18世纪：重视数据价值**——出现微积分、物理和数学等，人们开始重视数据的价值，出现基本图表，如折线图、条形图、饼图等。

#### 1.1.2 数据可视化定义 ⭐重点 📖必背

> 数据可视化旨在借助图形化的手段，将一组数据以图形的形式表示，并利用数据分析和开发工具发现其中未知信息的处理过程。——第1章 1.1.2

#### 1.1.3 数据可视化过程

可视化其实是一个**抽象的过程**，它可以简单地理解为将一个不易描述的事物形成一个可感知画面的过程，也就是**从数据空间到图形空间的映射**。⭐重点 📌考点

#### 1.1.4 数据可视化目的 ⭐重点 📖必背

数据可视化是为了从数据中寻找三个方面的信息：**模式、关系和异常**。

- **模式**，指数据中的规律。比如，城市交通流量在不同时刻差异很大，而流量变化的规律就蕴含在海量传感器源源不断传来的数据中。如果能及时从中发现交通运行模式，就可以为交通的管理和调控提供依据，进而减轻堵塞现象。

#### 1.3.2 matplotlib概述 ⭐重点 📌考点

matplotlib官网提供了三种API：**pyplot API、object-oriented API、pylab API**（pylab API 原文仅列出名称，未展开说明（待确认））。

- **pyplot API**：使用pyplot模块开发的接口，封装了一系列与MATLAB命令同名的函数，使用这些函数可以像使用MATLAB命令一样快速地绘制图表。基本思路：(1)导入pyplot模块 → (2)调用该模块的绘图函数来绘制图表 → (3)展示图表。特点：**屏蔽了底层中画布、绘图区域的创建细节，它会持续跟踪当前的画布和绘图区域**。

```python
import numpy as np
import matplotlib.pyplot as plt
data = np.array([1, 2, 3, 4, 5])    # 准备数据，y值
# 在当前画布的绘图区域中绘制图表
plt.plot(data)
plt.show()                                   # 展示图表
```

![pyplot API 绘制的折线图运行结果](assets/images/ch01-s21-01.png)

*图1-14　pyplot API 绘图结果（来源：第1章 1.3.2，幻灯片第21页）*


- **object-oriented API**：面向对象的接口，封装了一系列对应图表元素的类，只有创建这些类的对象并按照隶属关系组合到一起才能完成一次完整的绘图。基本思路：(1)导入pyplot模块 → (2)创建画布（Figure类的对象）→ (3)在画布上添加绘图区域（Axes类的对象）→ (4)调用绘图方法绘制图表 → (5)展示图表。

```python
import numpy as np
import matplotlib.pyplot as plt
data = np.array([1, 2, 3, 4, 5])       # 准备数据
fig = plt.figure()                            # 创建画布
# 添加绘图区域，创建1x1的网格，并选择第1个（唯一）子图
ax = fig.add_subplot(111)
# ax = fig.add_subplot(1, 1, 1)
ax.plot(data)                                  # 绘制图表
plt.show()                                      # 展示图表
```

### 1.4 数据可视化的未来

#### 1.4.1 数据可视化面临的挑战 ⭐重点 📖必背

1. 数据规模大，已超越单机、外存模型甚至小型计算集群处理能力的极限，而当前软件和工具运行效率不高，需探索全新思路解决该问题。
2. 在数据获取与分析处理过程中，易产生数据质量问题，需特别关注数据的不确定性。
3. 数据快速动态变化，常以流式数据形式存在，需要寻找流式数据的实时分析与可视化方法。
4. 面临复杂的高维数据，当前的软件系统以统计和基本分析为主，分析能力不足。
5. 来源数据的类型和结构各异，已有方法在非结构化、异构数据方面支持不足。

#### 1.4.2 数据可视化的发展方向 ⭐重点 📖必背

数据可视化技术的发展方向可分为以下三个方面：

1. 与**数据挖掘**结合：揭示潜在规律，提升挖掘效率。
2. 与**人机交互**结合：支持友好交互，增强用户对数据的掌控。
3. 与**大规模、高维度、非结构化数据**结合：适应大规模、高维度、非结构化数据的可视化需求。

## 第2章 数据可视化基础（数据预处理）

### 2.1 数据预处理流程 ⭐重点 📖必背

数据预处理步骤如下：

1. **数据清理**：指修正数据中的错误、识别脏数据、更正不一致数据的过程。其中涉及的技术有不一致性检测技术、脏数据识别技术、数据过滤技术、数据修正技术、数据噪声的识别与平滑技术等。
2. **数据集成**：指把来自不同数据源的同类数据进行合并，减少数据冲突，降低数据冗余程度等。
3. **数据归约**：指在保证数据挖掘结果准确性的前提下，最大限度地精简数据得到简化的数据集。数据归约技术包括维归约技术、数值归约技术、数据抽样技术等。数据归约技术可以用于得到数据集的归约表示，它虽然小，但会保持原数据的完整性。因此，在归约后的数据集上进行挖掘也会产生相同(或几乎相同)的分析结果。
4. **数据变换**：指对数据进行规范化处理。数据转换处理技术包括基于规则或元数据的转换技术、基于模型和学习的转换技术等。

### 2.2 数据清洗

#### 2.2.1 缺失值的检测 ⭐重点 📌考点

- `isnull()` 和 `notnull()` 函数会接收一个 Series 类或 DataFrame 类的对象，返回一个跟原对象形状相同的新对象，新对象中的数据都是表示检测结果的布尔值。
- `isnull()`：检测到缺失值的位置标记 **True**，其他位置标记为 False。
- `notnull()`：检测到缺失值的位置标记 **False**，其他位置标记为 True。

#### 2.2.2 缺失值的处理 ⭐重点 📌考点

**删除缺失值**——pandas 提供 `dropna()`，会删除包含缺失值的一行或一列数据，并返回一个删除缺失值后的对象：

```python
dropna(axis=0, how='any', thresh=None, subset=None, inplace=False)
```

- `axis`：确定删除行或列，0 或 'index' 表示删除包含缺失值的**行**，1 或 'columns' 表示删除包含缺失值的**列**，默认值为 0。
- `how`：'any'（默认）表示有 NaN 时便删除整行或整列；'all' 表示只有所有值为 NaN 值时才删除整行或整列。
- `thresh`：表示保留至少有 N 个非 NaN 值的行或列。

**填充缺失值**——pandas 提供 `fillna()`，既可以使用指定的值填充，也可以使用缺失值前面或后面的有效值填充：

```python
fillna(value=None, method=None, axis=None, inplace=False, limit=None, downcast=None)
```

- `value`：用于填充的值，可以是标量、字典、Series 类或 DataFrame 类的对象。
- `method`：'pad'/'ffill' 前向填充，'backfill'/'bfill' 后向填充。⚠️易错点：method 参数不能与 value 参数同时使用。
- `limit`：可以连续填充的最大数量。

#### 2.2.3 重复值的检测 ⭐重点 📌考点

pandas 提供 `duplicated()`，默认情况下会对所有数据进行检测，检测标准为：只要一行数据与其他行数据的所有值是完全相同的，就会将其他行数据判定为重复值，并标记为 True，非重复值标记为 False。

```python
duplicated(subset=None, keep='first')
```

- `subset`：用于指定检测重复值的列索引或列索引序列，默认检测所有列。
- `keep`：'first'（默认）保留第一次出现的行；'last' 保留最后一次出现的行；False 表示值相同的所有行都被标记为重复值。
- 返回一个 Series 类的对象，索引对应被检测对象的行索引，数据是表示检测结果的布尔值。

### 3.3 使用Pyecharts绘图

#### 3.3.1 Pyecharts简介 ⭐重点 📌考点

绘图思路：**①创建图表类的对象 → ②添加图表用到的数据 → ③添加图表配置项 → ④渲染图表**。

Pyecharts 库的 charts 模块中提供了很多封装图表功能的图表类：

| 类 | 说明 | 类 | 说明 |
| --- | --- | --- | --- |
| Line | 折线图 | WordCloud | 词云图 |
| PictorialBar | 象形柱形图 | Map | 统计地图 |
| Bar | 柱形图/条形图 | HeatMap | 热力图 |

- **全局配置项**：针对图表通用属性（初始化属性、标题组件、图例组件、工具箱组件、视觉映射组件、提示框组件、数据区域缩放组件等），实例化后传入 `set_global_opts()`（InitOpts除外）。
- **系列配置项**：针对图表特定元素属性（图元样式、文本样式、标签、线条样式、标记样式、填充样式等），实例化后传入 `add()` 或 `add_xx()` 方法。
- **渲染图表**：`render()` 渲染到HTML文件（默认为程序根目录的 render.html）；`render_notebook()` 渲染到 Jupyter Notebook。

## 第4章 时间数据可视化

### 4.1 时间数据在大数据中的应用 ⭐重点 📌考点

- **时间数据**也称**时间序列**或**动态数据**，即同一现象或数据在不同时间点或时间段的数据序列。例如，同一只股票在一天中不同时间点或时间段所反映出来的数据序列，即是时间序列。
- 时间序列数据存在于社会的各个领域，如：天文观测数据、气象图像、临床诊断记录（包括病人的每次看病的病情记录以及心电图等扫描仪器的数据记录）等。金融和商业交易记录如股市每天的交易价格及交易量、超市中每种商品的销售情况等。
- 不管是延续性还是暂时性的时间数据，可视化的最终的目的就是从中**发现趋势**：看到什么已经成为过去，什么仍保持不变？找出它是在上升还是下降？造成这些变化的原因可能有什么？是否存在周期性的循环，是好还是坏？
![2001-2011年大学生就业率变化折线图](assets/images/ch04-s07-01.png)

*图4-1　2001-2011年大学生就业率变化（来源：第4章 4.1，幻灯片第7页）*


- **时间型数据**是按时间顺序排列的一系列数据值，包含时间属性，不仅要表达数据随时间变化的规律，还需表达数据分布的时间规律。时间型数据可以分为**离散型时间数据**和**连续型时间数据**两种。

### 4.2 连续型数据处理 ⭐重点 📖必背

**连续型数据**指任意两个数据点间可以细分出无限多个数值，它表现的是不断变化的现象。如：温度是连续型数据，可以测量一天内的任意时刻的温度，股市实时行情也是一种连续型数据。连续型数据可视化图表：**阶梯图、折线图、拟合曲线**。

#### 4.2.1 阶梯图 ⭐重点 📌考点

阶梯图是图形线条保持在同一个值，直到发生变化，直接跳跃到下一个值，形状类似于楼道内的楼梯。适用场景：银行利率一般会持续几个月不变，然后某一天出现上调或下调；或楼盘价格长时间停留在某个值，突然有一天因各种调控出现调整。

## 第5章 比例数据可视化

### 5.1 比例数据在大数据中的应用 ⭐重点 📌考点

- 比例数据是衡量**部分与整体关系**的重要指标，广泛存在于社会的各个领域：医疗健康领域（临床诊断中的白细胞分类计数、某种手术的术后感染率、特定药品在治疗方案中的使用频率）、工业生产与质量控制（生产线的良品率、原材料的利用率、项目预算中人力资源成本所占的比重）、社会统计（人口普查中的城乡人口比例、青少年网民在总体网民中的占比、某项公共政策的公众支持率）等。
- 比例数据是根据**类别、子类别和群体**来进行划分的。这里的群体不单单指的是人类群体，它代表着各种可能的选择和产出，也就是**样本空间（SampleSpace）**。
- 对于比例，通常想要得到**最大值、最小值和总体分布**。前两者较简单，将数据由小到大进行排列，位于两端的分别就是最小值和最大值。对于最小值和最大值没有必要用图表展现，**真正所感兴趣的应该是比例的分配**。

### 5.2 整体与部分 ⭐重点 📖必背

比例型数据可视化图表：**饼图、环形图、堆叠柱形图、堆叠面积图、矩形树图**。

#### 5.2.1 饼图 ⭐重点 📖必背

## 第6章 关系数据可视化

### 6.1 关系数据在大数据中的应用 ⭐重点 📖必背 🧗难点

- **因果关系（Why?）**：难以捉摸、验证成本高、过程漫长。例：为什么购入《考研英语真题》的人，通常还会买《考研政治》书？
- **相关关系（What?）**：快速发现、立即行动、驱动决策。例：购入《考研英语真题》的人，也很可能会买《考研政治》书吗？
![关联性示意图：事物间的关联容易被发现](assets/images/ch06-s11-01.jpg)

*图6-1　关联性示意（来源：第6章 6.2，幻灯片第11页）*


- 人们解决问题时，通常倾向于探寻事物的因果关系，而在**大数据场景下，更应聚焦事物的相关关系**，无需执着于难以界定的因果逻辑。相关关系虽无法解释事物的成因，却能精准提示事物的发生态势。
- 如，若能通过数据知晓购买机票的最佳时机，机票价格波动的深层原因便无需深究。**大数据的核心价值在于告知"是什么"，而非"为什么"。**
- 例：大豆的价格上涨，猪肉的价格可能也会上涨（已知：豆粕是猪饲料的关键成分），但大豆价格上涨可能并非猪肉上涨的原因。尽管如此，在此情况下仍可抓紧时间囤些猪肉，如此往往能省下一笔钱，至于背后是否存在因果关系，便没那么重要。⚠️易错点：**关联并不代表存在因果关系**。

### 6.2 数据的关联性 ⭐重点 📖必背

数据的关联性，指**量化的两个数据间的数理关系**。**散点图、散点图矩阵与气泡图**是探索和展示数据间关联性的常用可视化方法。
![数据关联性示意图：两个数据间的数理关系](assets/images/ch06-s12-01.jpg)

*图6-2　数据的关联性（来源：第6章 6.2，幻灯片第12页）*


**关联性强**，即一个数值变化时，另一数值也会随之发生相应变化；相反，**关联性弱**，一个数值变化时另一数值几乎没有变化。通过数据关联性，可根据已知的数值变化预测另一数值的变化。

#### 6.2.1 散点图 ⭐重点 📌考点

变量间一般有**三种关系**：**正相关、负相关和不相关**。正相关时，横轴数据和纵轴数据变化趋势相同；负相关时，横轴数据和纵轴数据变化趋势相反；不相关时，散点的排列则是杂乱无章的。

### 6.3 数据的分布性 ⭐重点 📖必背 🧗难点

思考题（原文）：五年级一班和二班数学考试平均分都是85分，但两班成绩分布天差地别——

- 五年级一班：85, 86, 84, 87, 85, 85, 86, 84, 85, 83（排序：83, 84, 84, 85, 85, 85, 85, 86, 86, 87）——**分布集中**；
- 五年级二班：100, 95, 90, 85, 85, 85, 70, 65, 60, 55（排序：55, 60, 65, 70, 85, 85, 85, 90, 95, 100）——**分布分散**。

观察发现，两组数据中的**众数、中位数、平均数皆相同**，但数据内部的分布情况却天差地别。平均数、中位数等统计量如同个人的身高与体重，仅能提供数据的局部指标；而**数据的分布形态**则像一张全身照，揭示了其是否匀称、何处强健、何处薄弱——它描绘的是数据的完整轮廓。⭐重点 📌考点

**茎叶图、直方图与密度图**是探索和展示数据分布性的常用可视化方法。

#### 6.3.1 茎叶图 ⭐重点 📌考点

茎叶图的基本思想：将数组或序列中**变化不大或不变的数位作为茎(主干)**，将**变化大的数作为叶(分枝)** 排在茎的后面，读者就可以直观地看到茎后面有多少叶，并且每个数的数值是多少。
![茎叶图基本框架：茎为主干，叶为分枝排在茎后](assets/images/ch06-s52-01.png)

## 第7章 复杂数据可视化

### 7.1 高维多元数据在大数据中的应用 ⭐重点 📖必背

- **高维**：数据具有多个属性/特征。核心是"数量"，只关心特征有多少个，是一个**定量的概念**。
- **多元**：观察对象由多个指标共同描述。核心是"种类"，关心特征是不是不同的类型、来自不同的角度，是一个**定性的概念**。
- 例：只从"财务"一个角度但用1万个指标描述 → 是**高维数据**但不是多元数据；从人口统计、健康、消费行为、社交网络、地理位置等多个角度、每个角度又用成千上万个指标刻画 → **既是高维也是多元**的数据。

常规的可视化方法：**散点图**将各属性的值映射到不同的坐标轴，并确定数据点在坐标系中的位置；当数据维度超过2时，若需表示更多的属性，如颜色、大小、形状等，则可以通过各种**视觉编码**来实现。⚠️易错点：**视觉编码的种类有限，且过多或过于复杂的视觉编码会降低可视化可读性**。

### 7.2 非结构化数据可视化 ⭐重点 📌考点

#### 7.2.1 基于并行的大尺度数据高分辨率可视化

复杂数据并不只有高维度数据，还有**异构数据**等。**异构数据**，指在同一个数据集中存在的如结构或属性不同的数据情况，存在多个不同种类节点和连接的网络被称为**异构网络**。异构数据常采用**网络结构**进行表达。

**"异构"VS"同构"**：同构数据——一箱苹果，每个数据单元（苹果）都是同一类型，属性相同（都有重量、颜色、甜度）；异构数据——整个水果摊，摊上有苹果、香蕉、橙子、西瓜，每种水果（数据类型）属性不同（苹果有"脆度"，香蕉有"弯曲度"，西瓜有"籽的数量"），其属性有所不同，但共同构成"水果摊"。⭐重点 📌考点

数据的异构性大多产生于**数据源不同的获取方式**，如微信用户数据集中不仅包括软件的点对点的聊天记录、GPS位置数据，也包括用户的部分个人信息；这些来自不同数据源的数据通常具有不同的数据模型、数据类型和命名方法等，故对底层数据进行**整合**至关重要。**数据整合**为可视化模块，为众多独立和异构的数据源获取数据提供透明且统一的访问接口。
![高性能计算和可视化集群架构图：计算节点、显示节点、存储节点经InfiniBand网络互联](assets/images/ch07-s80-01.png)

*图7-21　面向高性能计算和可视化的计算集群架构（来源：第7章 7.2.1，幻灯片第80页）*


全方位显示大尺度数据的所有细节是一个**计算密集型**的过程，处理大尺度数据的基本技术路线就是**大规模计算集群**（如美国马里兰州大学构建的GPU和CPU混合式高性能计算和可视化集群）。大规模数据的高清可视化需适配相应的显示设备，因专业级高精度大屏非普通用户标配，故通常采用两种方法在有限分辨率下实现大尺度数据的可视化：**一是将数据按层次结构重组；二是将高精度数据采样为低分辨率数据进行预览**。

**"可视化数据库"思想**（Cleverland等人）：将多窗口、多页面的可视化结果视为一个集合，借用数据库方法对其进行统一生成、存储、管理与交互。其核心任务：**①数据划分**；**②视图生成**；**③存储管理**；**④交互联动**。

#### 7.2.2 分而治之的大尺度数据分析与可视化 ⭐重点 📌考点

**分而治之**是可视化领域及计算机图形学中的一种标准方法。

- ① **统计分析层的分而重组**：R语言是一门面向统计分析底层的开源语言，虽然基于单线程运行，但可通过大量软件开发包实现多核并行计算。然而，即使是并行的方式也并不能解决大尺度数据的分析难度，一种新颖思路便是将数据划分为子集，对这些子集使用相关方法来进行可视化的操作，最后合并总体结果，这种方式被称为**分而重组**。
- ② **数据挖掘层的分而治之**：大数据分类的分而后合方法大体分为三个步骤：首先，输入数据或文本信息，将其**等分为n份或按规则划分**，对每份数据使用**最适合的分类器**进行分类并将分类结果**融合**，最后通过**强分类器**计算获取最终结果。
- ③ **数据可视化的分而治之**：大规模科学计算的结果适合采用**多核并行模式**实现加速和分而治之的处理，因其通常体现为规则的空间型数据。目前比较流行的 **Hadoop 和 MapReduce** 等处理框架通常被用来处理非空间型数据，将 MapReduce 框架应用于科学计算的空间型数据，意味着科学计算的空间型数据和非结构化数据可以在统一的数据分而治之的框架下处理。

### 7.3 数据不准确性可视化 ⭐重点 📖必背

#### 7.3.1 不确定性的来源 ⭐重点 📌考点

数据的**收集、处理和可视化的过程皆会产生不确定性**。如：测量数据时，测量仪器的优劣及技术人员的测量水平会给实际所测数据带来不确定性；同样，不同仿真模型也会造成数据的不确定性。因此，在对原始数据进行可视化之前要对数据进行**清洗过滤**操作，而这些操作可能在一定程度上会**改变原始数据**，也就存在潜在的不确定。

#### 7.3.2 不确定性的可视化方法 ⭐重点 📖必背

目前不确定性可视化方法可大致分为**四类：图标法、几何体表达法、视觉元素编码法和动画表达法**。

- **① 图标法**：常见的可视化图表有**误差条、盒须图**等。**误差条**由一系列带标记的线条组成，用来可视化一维不确定性数据；误差条的横轴一般表示数据实体，纵轴表示每个数据实体的统计特征，通常情况下，纵轴至少由**均值、下限误差值和上限误差值**组成。**盒须图**又名箱线图，五数统计图是一种最基本的盒须图，其包括上下边缘值（即最大和最小值）、上四分位数、中位数和下四分位数。对于二维确定性向量场，常用箭头等图标表示：**箭头表示风向，箭头长度表示风的强度，箭头宽度表示风向的不确定性**（纤细的箭头代表不确定性较小，粗壮的箭头则说明不确定性较大）。⚠️易错点：大量图标布局会造成严重的遮盖进而导致视觉混乱，故**图标法适合稀疏不确定性数据的可视化**。

- **② 几何体表达法**：利用代表性的几何物体表达数据的不确定性，常用的基本几何物体有**点、线、面、网格、体**等；通常点线等简单几何体仅能编码**一维**不确定性数据，而对于一些高维度数据的不确定性，可采用较复杂的几何体表示。优点：可视化结果较形象直观且易于理解，相较于图标法还能表达高维度的不确定性。缺点：在引入代理几何体表示不确定性时会**干扰原有的可视化结果**，会让用户潜意识里认为这些几何体是数据的组成部分，而非不确定性的可视载体。⚠️易错点
- **③ 视觉元素编码法**：以视觉元素作为不确定性编码的基本载体。基本的视觉标量包括**位置、形状、亮度、颜色、方向和纹理**等，其中**颜色**是表达不确定性的常用视觉元素之一。优点：用户可快速定位可视化结果中不确定性所在的区域和大小。⚠️易错点：对视觉元素的选择往往与用户的心理和感知有着极大的联系，需选择合适的视觉元素以编码不确定性。
- **④ 动画表达法**：一种基于动态信息表达的方法。若要发觉数据中不确定性所在的大小、范围等信息，就要求用户**持续关注**可视化的结果。众多动画相关参数皆可用于编码不确定性，如：**速度、时间单位、关键帧、闪烁、运动范围**等。缺点：需要用户长时间且连续观察动画才会找到不同帧间的差别，故需比静态可视化更长的理解曲线；另外，动画中的跳动、闪烁等不确定性表达方式还易引起**视觉疲劳**。⚠️易错点

> **本章小结（原文）**：本章节介绍高维多元数据在大数据中的应用，分析目前已有的二三维方法可视化的局限性。针对过多或过于复杂的视觉编码会降低可视化的可读性问题，本节具体讲解了非结构化数据可视化及数据不准确性的可视化。

## 第8章 数据可视化中的交互

### 8.1 交互设计 ⭐重点 📌考点

- **交互设计概念**：交互设计，是**人工制品、环境和系统的行为，以及传达这种行为的外形元素的设计与定义**。
- 交互设计就是**给一个或一系列交互行为设计剧本**。如：事先规定输入框的字数限制是多少，什么情况是正确的，什么情况是错误的，在正确的时候有什么反馈，在错误的时候有什么反馈，这些都会像是剧本里的故事情节和台词一样被提前设计好，并由演员（图形界面）表演出来；用户在此过程中，既是**观众**（观看情节发展）亦是**演员**（与图形界面互动，触发情节）。
- **交互设计师的工作**：如果交互设计是给交互行为写剧本，那么交互设计师就是**编剧**，负责构思、撰写和修改这个剧本。剧本大概包括：【主线】打开App→搜索关键词→筛选→查看详情→导航到达→评价；【剧情】在哪个页面找到搜索，搜索在什么位置，点击哪个按钮进入搜索，App在什么情况下给出怎样的提示；【分支剧情】插播一条广告，推荐相似的商家；【大结局】最终找到符合要求的餐厅。
- 思考：交互设计师 ＝ 画流程图、线框图？——说法较片面，但非全错，因流程图线框图确实是交互设计师进行设计的一种产出方式；但此说法忽略了在这些可视化产出物之外，设计师所进行的**思考工作**。

### 8.2 交互设计原则 ⭐重点 📖必背

交互的设计方法有很多，每种分类都有各自依据和应用场景，**没有一种设计方法可以适应所有的应用需求**。但必须依据一定的设计原则进行可视化交互。六条原则：

1. **从用户角度出发。**
2. **亲密性（分组）**：相同部分的内容，彼此相关，应互相靠近；不同部分的内容，应明显区隔开。
![亲密性原则示例：相关内容互相靠近，不同内容明显区隔](assets/images/ch08-s10-01.png)

*图8-1　亲密性原则（来源：第8章 8.2，幻灯片第10页）*


3. **按交互操作类型分类**：本·施耐德曼将常见的交互操作归纳为：**缩放、过滤、关联、记录、提取、按需要提供细节及概览**。根据所操作的数据类型可将交互操作分为三类：**图形操作**（对可视化对象进行操作，如对图形等视觉表面层面的操作）、**数据操作**（对数据对象进行增加、修改和删除等操作）、**集合操作**（对数据对象组成的集合进行创建和删除等操作）。⭐重点 📌考点
4. **布局**：在版式布局上，通常通过**对齐**使每个元素与其它元素建立起某种视觉联系。对齐不仅包括左对齐、右对齐、顶端对齐、低端对齐，还包括水平居中、垂直居中、横向分布、纵向分布等。
![布局对齐示例：元素间通过对齐建立视觉联系](assets/images/ch08-s12-01.png)

*图8-2　布局对齐示例（来源：第8章 8.2，幻灯片第12页）*

![布局对齐示例（二）](assets/images/ch08-s12-02.png)

*图8-3　布局对齐示例（二）（来源：第8章 8.2，幻灯片第12页）*


5. **对比/强调**：做可视化设计的初心是以图文的形式把所要表达的信息清晰传递给用户，让用户一目了然。为此，需**强调重点，弱化次要**，避免作品中所有的元素看起来同等重要的情况出现。若想突出某些信息要点，则应让对应的元素（**字体、颜色、大小、线宽、形状、空间**等）与其它元素不相同，以让用户首先关注到他们。

6. **表达力度**：表达，力求**准确、到位、简洁、易懂**。当用户看到可视化作品时，最好要保证所表达的信息能被用户正确理解。除上面六个原则外，还应附加一些辅助信息，如文字、箭头等；在可视化作品中，文字必不可少，但**篇幅要加以控制**。文字的表达，要准确、到位、简洁、易懂，要能引导用户正确地理解图表的意思，且不引起任何歧义。

### 8.3 交互设计流程 ⭐重点 📖必背

交互的设计形式有很多种，不同形式的数据可视化流程有所不同，本节主要讲重要且相通的部分，共四步：

1. **了解需求**：(1)看什么，即哪些内容需要可视化；(2)谁看，即用户是谁；(3)在哪里看，即有哪些可视化形式；(4)什么情况下看。
2. **可视化设计**：(1)梳逻辑；(2)定风格，即营造氛围，驱动用户沉浸式阅读；(3)排版式，可视化作品一般包括标题、正文、图表、说明文字等要素，版式就是基于以上原则，确定元素间的层次结构，合理摆放这几种要素；(4)选图表；(5)调细节。
3. **指标计算**：设计图表时需注意**模拟数据和真实数据是有区别的**。根据模拟数据设计的图表，一定要用**真实数据展现与验证**，验证图表与真实数据的契合程度。⚠️易错点
![模拟数据与真实数据对比图：模拟数据差异明显，真实数据看起来都一样](assets/images/ch08-s19-01.png)

*图8-7　模拟数据与真实数据展示差异（来源：第8章 8.3，幻灯片第19页）*


4. **前端开发**：数据产品、大屏的可视化实现，还需前端开发。理论上，只要设计出图表，就一定能在前端实现，但可能会受到前端开发人员的技术水平和展现工具的限制，故可视化设计有时候需要寻求一种关于**设计与实现间的平衡**。可视化设计人员最好事先有所评估，采用复杂图表设计前最好与开发人员沟通探讨实现的可行性。

### 8.4 使用Seaborn绘图 ⭐重点 📌考点

Matplotlib 虽然已经是比较优秀的绘图库了，但是它有一个非常令人头疼的问题，那就是 **API 使用起来过于复杂**，其内部有上千个函数，且每个函数都有非常多的参数。**Seaborn 基于 Matplotlib 进行了更高级的封装**，相比 Matplotlib 可以轻松地画出漂亮的图表，使图表的配色更加舒服，以及图表元素的样式更加细腻。

- 处理一组数据之前，通常需要提前了解这组数据具体是怎样分布的：**单变量**数据采用**直方图或核密度曲线**；**双变量**数据可以通过**散点图、二维直方图、核密度估计图形**等进行展示。
- `displot()` 默认绘制直方图；`kind='kde'` 绘制核密度估计曲线；`rug=True` 显示密度观察条。**核密度估计曲线**通过在每个数据点周围放置一个核函数，并通过调整核函数的宽度得到一个平滑的曲线；曲线的高度表示数据点密度的大小，曲线顶部对应着数据点最多的区域，曲线底部对应着数据点最少的区域。
- `jointplot()` 绘制散点图、二维直方图、二维密度图，反映两个变量之间的关系，以及每个变量在单独坐标轴上的分布情况。
- **分类数据**是按照现象的某种属性对其进行分类或分组而得到的反映事物类型的数据（例：企业按照经济性质被分为国有、集体、私营、其他经济这几类）。
- `stripplot()` 根据分类数据绘制散点图（数据点可能互相重叠）；`swarmplot()` 绘制的散点图所有数据点不会重叠；**箱形图和小提琴图**可查看每个分类下数据的分布情况——其中箱形图可以查看数据的**四分位的分布**情况，**小提琴图结合了箱形图与核密度图的特征**，用于展示多组数据的分布状态以及概率密度；`barplot()` 默认显示**误差线**；`pointplot()` 显示点和误差线，点代表平均值或其他估计值，误差线代表**置信区间**。

> **本章小结（原文）**：本章主要讲了交互设计的概念、原则、流程，以及怎样用Seaborn库绘制基础图表，其中包括适合单变量数据的直方图或和核密度曲线，以及适合双变量数据的散点图、二维直方图、核密度估计图形等。

## 附录二：精华摘抄（原文引用）

> 数据可视化旨在借助图形化的手段，将一组数据以图形的形式表示，并利用数据分析和开发工具发现其中未知信息的处理过程。——第1章 1.1.2

> 可视化其实是一个抽象的过程，它可以简单地理解为将一个不易描述的事物形成一个可感知画面的过程，也就是从数据空间到图形空间的映射。——第1章 1.1.3

> 数据可视化是为了从数据中寻找三个方面的信息：模式、关系和异常。——第1章 1.1.4

> 俗话说"百闻不如一见""一图胜千言"。——第1章 1.2

> 数据归约：指在保证数据挖掘结果准确性的前提下，最大限度地精简数据得到简化的数据集……在归约后的数据集上进行挖掘也会产生相同(或几乎相同)的分析结果。——第2章 2.1

> 面元划分是指连续数据被离散化处理，按一定的映射关系划分为相应的面元，这里的面元可以理解为区间。——第2章 2.5.1

> 为了将类别类型的数据转换为数值类型的数据，类别类型的数据在被应用之前需要经过"量化"处理，使之转换为哑变量。——第2章 2.5.2

> 直方图又称质量分布图，它由一系列高度不等的矩形条或线段组成，用于反映数据分布和波动情况。——第3章 3.1.2

> 箱形图又称盒须图、箱线图，是利用数据中的5个统计量——最小值、第一四分位数、中位数、第三四分位数和最大值——描述数据的一种图表。——第3章 3.1.2

> 词云图是由词汇组成类似云朵的彩色图形……每个词出现的频率代表的是词的重要性，以字号大小表示，字号越大，说明这个关键词越重要。——第3章 3.3.3

> 气泡图是散点图的一种变体，通常用于展示三个变量间的关系……如果气泡使用了不同的颜色，那么此时的气泡图也可以用于展示四个变量之间的关系。——第3章 3.3.4

> 不管是延续性还是暂时性的时间数据，可视化的最终的目的就是从中发现趋势。——第4章 4.1

> 阶梯图是图形线条保持在同一个值，直到发生变化，直接跳跃到下一个值，形状类似于楼道内的楼梯。——第4章 4.2.1

> 堆叠柱形图……如果数据存在子分类，并且这些子分类相加有意义的话，此时就可以使用堆叠柱形图来表示。——第4章 4.3.2

> 饼图以环状方式呈现各分量在整体中的比例……所有扇形所占百分比的总和应等于100%，若不等，表明出现错误。——第5章 5.2.1

> 矩形树图是一种基于面积的可视化方式，通过每一个板块（通常为矩形）的尺寸大小进行度量。外部矩形代表父类别，而内部矩形代表子类别。——第5章 5.2.4

> 堆叠面积图能呈现比例数据随时间的变化情况，不仅可以看到整体变化趋势，也可看到其中每一类的变化情况。——第5章 5.3

> 大数据的核心价值在于告知"是什么"，而非"为什么"。——第6章 6.1

> 平均数、中位数等统计量如同个人的身高与体重，仅能提供数据的局部指标；而数据的分布形态则像一张全身照，揭示了其是否匀称、何处强健、何处薄弱——它描绘的是数据的完整轮廓。——第6章 6.3

> 核密度估计通过为每个数据点赋予一个平滑的"核函数"，并将所有数据点对应的核函数叠加，最终归一化形成一条平滑的概率密度曲线。该曲线下的总面积恒为1。——第6章 6.3.3

> 当数据维度非常高时（如超过50维），各类可视方法都无法将所有数据细节清晰地呈现出来。——第7章 7.1.1（降维）

> 雷达图的维度不是越多越好，一般5-8个最清晰，最适合用来展示一个对象的整体面貌。——第7章 7.1.2

> 异构数据：一箱苹果是同一类型；而整个水果摊上，每种水果（数据类型）属性不同，但共同构成"水果摊"。——第7章 7.2

> 全方位显示大尺度数据的所有细节是一个计算密集型的过程，处理大尺度数据的基本技术路线就是大规模计算集群。——第7章 7.2

> 目前不确定性可视化方法可大致分为四类：图标法、几何体表达法、视觉元素编码法和动画表达法。——第7章 7.3

> 交互设计，是人工制品、环境和系统的行为，以及传达这种行为的外形元素的设计与定义。——第8章 8.1

> 根据模拟数据设计的图表，一定要用真实数据展现与验证，验证图表与真实数据的契合程度。——第8章 8.3
